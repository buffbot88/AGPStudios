## Decisions locked in (do not revisit during this build)

- **Stack.** Rust (cargo 1.92 confirmed locally). `axum 0.7` + `tokio`. Frontend: Vite 6 + Phaser 3 + TypeScript 5.
- **Reuse strategy.** Hybrid — keep the **config schema**, **row-router logic shape**, **intent-classifier shape**, and **demand pool mechanics** from `../archive/AshatIntentRouter`. Fresh HTTP layer. Fresh auto-discovery. Frontend fully ported from `../archive/AshatNeuralHost`.
- **Auth.** Single `ASHAT_KEY`. Seeded verbatim from the existing concrete value in `../archive/AshatIntentRouter/server-config.json` so existing clients keep working with no re-issuance. No "warn on default" branch.
- **`llama-server` discovery.** Priority: `server.orchestrator_binary_default` (config) → `ASHAT_LLAMA_BIN` env override → `PATH` lookup.
- **Git (since v6.2).** The master is a git repo on GitHub (`buffbot88/ashatnueralhost`, branch `main`). Secrets and runtime data (`server-config.json`, `oraclehost_id_rsa`, `models/`, `target/`, `logs/`, `workspaces/`) are gitignored; `server-config.example.json` is the tracked template. Sync via `scripts/github_sync.sh` or `POST /api/admin/github_sync` — see `Beta_Delta.md`.
- **No fail-fast.** Bounded FIFO queues on both pools. `503` only on true OS-level spawn failure or queue-head ageing past `inference.timeout_seconds`.

### Intent router model (locked after live probing)

The orchestrator router runs **`LFM2.5-VL-450M-Q4_K_M.gguf`** (LiquidAI VL
instruct, 229 MB). The original `LFM2.5-230M` could not follow the
one-word-classification instruction at all (it always emitted `"chat"`),
which silently dead-ended the Phase 6 `Intent::Code` path. Candidate models
were probed live against a fixed battery (4 code / 4 chat / 2 status / 1
unknown):

| Model | code→code | non-code→code (false +) | size | latency (1-core) |
| ----- | --------- | ------------------------ | ---- | ---------------- |
| LFM2.5-230M (original) | 0/4 | — | 153 MB | ~2 s |
| LFM2.5-350M | 2/3 | 0 | 229 MB | ~2.6 s |
| LFM2-700M | 4/4 | 0 | 469 MB | ~6.9 s |
| SmolLM2-1.7B | 4/4 | 0 | 1056 MB | ~6.6 s |
| **LFM2.5-VL-450M** | **4/4** | **0** | **229 MB** | **~3.2 s** |

LFM2.5-VL-450M ties the bigger models on the one decision that changes
routing (code vs not) at half the RAM of LFM2-700M, and it loads in the
custom `llama-server` build without the vision `mmproj`. The classifier
prompt is a compact few-shot + `Intent:` completion prefix (`max_tokens: 16`)
— a bare "respond with one word" instruction makes small models echo the
user text instead.

## Request flow under concurrent users

1. **Client** → `POST /v1/chat/completions` with header `X-Ashat-Key: ASHAT_KEY`.
2. **Orchestrator classify.** The router asks the VL-450M Orchestrator pool:
   1. Always-on baseline on `18079`.
   2. If saturated, acquire an instance from `ports_extra` (`18078` → `18077`).
   3. If every extra port is busy, queue with `inference.timeout_seconds` cap.
3. **Assign to Coding Agent.** With the intent classified, router acquires a 1.2B Coding Agent slot:
   1. Try `18080`, then `18081`, then `18082`.
   2. If the chosen port has no running `llama-server`, spawn one carrying the 1.2B GGUF, poll `/health` until ready.
   3. If all three ports are busy, queue with `inference.timeout_seconds` cap.
4. **Proxy.** Forward the prompt to `http://127.0.0.1:{port}/v1/chat/completions`. Stream the response back to the caller. The 1.2B `tokio::process::Child` is wrapped in an RAII `InstanceGuard` keyed to the port.
5. **Hand off.** When the streaming response completes (or the client disconnects), `InstanceGuard::Drop` issues `start_kill()` and reclaims the port into the free set. Same shape for VL-450M extras on `ports_extra`. The baseline on `18079` never dies; `supervision.rs` respawns only on death.
6. **Record.** `MetricRecord { ts, intent, target_pool, target_port, success, latency_ms, error? }` appended to `logs/metrics.jsonl`.

`503` triggers (and only these): spawn fails `spawn_attempts_before_503` times in a row, OR queue head waits longer than `inference.timeout_seconds`, OR baseline VL-450M `/health` failing after `spawn_attempts_before_503` retries. Each trigger reason is reported via `/api/public_status`.

**Row-chain routing (v6.2).** The chat handler routes requests through
`RowRouter::pick()` — a smooth weighted round-robin over the enabled backends
(`omega 2 / beta 1 / delta 1`) with concurrent `/health` probes — in addition
to the local pool flow above. Requests landing on Beta / Delta go cross-server
(authenticated with each backend's `api_key`); local ones follow steps 3–6.
See `Beta_Delta.md` for semantics and the live verification.

## Boot ordering (in `crates/omega-server/src/main.rs`)

1. `config::AppConfig::load()`.
2. Resolve `llama-server` binary.
3. Discover GGUF paths via `models.rs`.
4. Build `OrchestratorPool` with baseline on `18079`. Spawn baseline `llama-server`. Poll `/health` until ready. **Do not proceed until healthy.**
5. Build `CodingAgentPool` (empty — instances spawn on demand).
6. Set up metrics store + supervision tick.
7. Bind axum to `0.0.0.0:8080`.
8. Install signal handlers: on `SIGTERM` / `SIGINT`, walk active `InstanceGuard`s, `start_kill()` each, then drop.

## Workspace migration (v2 — modular crates)

Phase 1 shipped as a single Cargo crate (`src/`). v2 splits it into a Cargo
workspace of three crates. Behavior is unchanged; the binary keeps the name
`ashat-neural-host-master` and still lands at `./target/release/`.

| Crate | Modules | Responsibility |
| ----- | ------- | -------------- |
| `omega-common` | `types`, `config`, `models`, `metrics`, `log`, `workspace` | Shared foundation: types, config + env overlay, GGUF discovery, JSONL metrics, tracing init, coding-agent workspace dirs |
| `omega-core` | `demand`, `queue`, `orchestrator`, `proxy`, `router`, `supervision`, `tool_loop`, `skill_db` | Inference engine — spawn-on-demand pools, intent classification, weighted row-chain routing, tool loop, supervision. No HTTP surface. |
| `omega-server` | `main`, `handlers`, `auth`, `alpha_status` | axum binary `ashat-neural-host-master` |

Migration decisions (locked):

- `metrics.rs` lives in **omega-common**, not the server: `demand`,
  `orchestrator`, `proxy`, and `supervision` (all `omega-core`) write
  `MetricsStore` records directly, and core must not depend on the server.
- `router.rs` (weighted round-robin row-chain router) moved into **omega-core**; the server calls `RowRouter` through the crate boundary.
- New `workspace.rs` (omega-common): `AgentWorkspace` ensures
  `workspaces/agent-{port}/` per spawned 1.2B and appends one `session.jsonl`
  request line per call. Config key: `workspace.dir` (default `workspaces`).
- New `alpha_status.rs` (omega-server): `AlphaReporter` POSTs the master's
  status snapshot to the Ashat Hub when `hub.enabled: true` (default `false`
  keeps it inert, mirroring how row-chain backends are gated by `enabled`).
  Config key: `hub.url`.

Build/run: `cargo build --release` (workspace) →
`./target/release/ashat-neural-host-master`. Per-crate:
`cargo build -p omega-core`, `cargo test -p omega-core`, etc.

## Phase 6 — Advanced Coding Agent with tools (done)

When the VL-450M router classifies a request as `code` on the omega lane,
`handlers.rs`
routes it to `ToolLoop` (`crates/omega-core/src/tool_loop.rs`) instead of the
plain proxy. The loop holds one 1.2B slot and iterates model → tool →
observation until the model answers (`{"answer": "..."}`) or the budget
(`tool_loop.max_iterations`, default 5) is spent.

- **Action format:** prompt-engineered JSON, `{"tool": "...", "args": {...}}`
  or `{"answer": "..."}`; prose-wrapped JSON blocks parse too, and *all*
  balanced JSON blocks are scanned — an `answer` block anywhere wins over a
  preceding `tool` block, because small models often emit
  `{"tool": ...} {"answer": ...}` concatenated. Unparseable model output is
  fed back as an error observation, and the last model text is the fallback
  answer when the budget runs out.
- **Tools (workspace-scoped to `workspaces/agent-{port}/`, path escapes
  rejected):** `list_dir`, `read_file`, `write_file`, `run_command` (cwd
  pinned, `tool_loop.command_timeout_seconds`, output capped), `validate`,
  `skill`, and `finish`/`answer`.
- **Script Validation Engine:** `validate` syntax-checks Python (`ast.parse`),
  JS (`node --check`), shell (`bash -n`), and JSON; on `finish` every file
  written during the run is swept and the report rides back in
  `ChatResponse.validation` so Ashat Hub receives debugged artifacts.
- **Skill tool:** implemented against MySQL (`SELECT content FROM skills WHERE
  name = ?`) but inert — `skills_db.enabled` is `false` by default, and the
  mysql client compiles only with `--features omega-core/skills-db` (avoids
  the flate2/openssl build stack until the DB details exist).
- **RAM/CPU tuning:** `inference.llama_mlock` passes `--mlock` (model pinned in
  RAM → fewer page-fault stalls = less wasted CPU); threads stay
  `inference.llama_threads`.
- **Hub countdown:** active tool-loop runs are tracked in `MetricsStore`
  (`mark_run_start` / `mark_run_finish`); `alpha_status.rs` posts
  `countdown.active_runs` with `elapsed_seconds` / `eta_seconds` per port on
  every hub tick, keeping the Hub session open with a live project ETA. A run
  with no prior completed-request reference falls back to a 60 s ETA baseline
  so the *first* run still shows a countdown.
- **Streaming:** the loop runs non-streaming; `stream: true` clients receive
  the final answer as a single SSE event + `[DONE]`.

Config keys: `tool_loop.{max_iterations, command_timeout_seconds,
output_max_chars}`, `skills_db.{enabled, host, port, database, user,
password}`, `inference.llama_mlock`. Tests: action parsing, path-escape
rejection, tool executors, `validate`, and a full loop driven by a scripted
mock model.

## Risks (build-time, ordered by severity)

| Severity | Title | Detail |
| -------- | ----- | ------ |
| High | Cold-start latency on every 1.2B | `llama-server` + 730 MB GGUF load is multi-second per agent. Accepted by spec; tracked in `/api/public_metrics`. |
| High | Q4_K_M precision loss | One-word intent classification by the VL-450M router may misclassify. Mitigation: deterministic prompt (`temperature: 0`, `max_tokens: 8`); monitor unknown-rate. |
| Medium | Concurrent cap of 3 × 1.2B | 4th caller queues. No `503` unless queue head ages out. |
| Medium | Orphan children on Rust crash | Spawned `llama-server` may leak if Omega aborts. Mitigation: `kill_on_drop` where supported + walk active guards on shutdown signal. |
| Medium | Baseline VL-450M blocks public bind | Axum `:8080` does not open until baseline VL-450M `/health` returns ok. Spec-intent: never serve unauthenticated traffic during orchestrator outage. |
| Low | GGUF discovery hits filename change | Hints/fallback may match nothing. Mitigation: hints overridable in config. |
